# Demostración de Web APIs — Propósito y Valor

> Este es un proyecto **educativo y de portafolio**, sin modelo de ingresos. En vez
> de un Lean Canvas comercial, este documento describe por qué existe y a quién sirve.
>
> **Última actualización**: 2026-07-02

## 1. Problema

- La documentación de las Web APIs (p. ej. MDN) es excelente pero extensa; falta un
  lugar donde **ver el ejemplo mínimo funcionando** de inmediato.
- Muchos ejemplos en la web arrastran frameworks o builds que **ocultan** la API real.
- **Alternativas actuales**: leer MDN, buscar en blogs, o armar un playground propio.

## 2. Audiencia

| Segmento                       | Descripción                                              |
| ------------------------------ | ------------------------------------------------------- |
| Estudiantes de desarrollo web  | Aprenden JavaScript y la plataforma web desde cero       |
| Docentes / creadores de contenido | Necesitan demos claras para clases y talleres         |
| Desarrolladores con experiencia | Buscan un recordatorio rápido y copiable de una API      |

- **Uso ideal**: alguien que quiere entender una Web API concreta en 2 minutos.

## 3. Propuesta de valor

- Ejemplos **mínimos, sin dependencias y copiables**, cada uno enfocado en una API.
- Código legible directamente en el navegador, sin build ni configuración.
- Interfaz coherente y con tema claro/oscuro que no distrae del concepto.
- **En una frase**: "un playground de referencia de las Web APIs nativas".

## 4. Cómo aporta valor (el producto)

| Capacidad                      | Qué resuelve                                             |
| ------------------------------ | ------------------------------------------------------- |
| Menú por API                   | Encontrar rápido el ejemplo que interesa                 |
| Página + script autocontenidos | Copiar un ejemplo y adaptarlo sin desenredar dependencias|
| Feature detection y mensajes   | Entender soporte, permisos y errores de cada API         |

## 5. Distribución

- Repositorio público en GitHub (código y documentación abiertos).
- Potencial despliegue estático (GitHub Pages) para consulta directa en el navegador.
- Difusión a través de [brayandiazc.com](https://brayandiazc.com) y redes.

## 6. Sostenibilidad

- **Costos**: prácticamente nulos (hosting estático gratuito, sin servicios de pago).
- **Mantenimiento**: aportes de la comunidad vía PRs (ver [CONTRIBUTING](../../CONTRIBUTING.md)).
- **Apoyo**: patrocinio opcional vía GitHub Sponsors.

## 7. Métricas de éxito

- Estrellas/forks del repositorio y PRs de nuevos ejemplos.
- Cobertura de APIs (número de ejemplos y su claridad).
- Uso como material de referencia en clases y talleres.
